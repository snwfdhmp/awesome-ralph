# Contribution Guidelines

Thank you for your interest in contributing to Awesome Ralph.

This list is a curation, not a collection. Only resources that help people understand, run, or improve Ralph loops belong here.

## Adding a Resource

Make sure your pull request follows these guidelines:

- Search the list and previous pull requests first, to avoid duplicates.
- Open one pull request per suggestion.
- Use the format `- [Resource Name](link) - Description.`
- Start the description with an uppercase letter and end it with a period.
- Describe what the resource is or does, objectively. Avoid marketing words like "awesome", "best", "powerful", or "revolutionary".
- Keep the description to one sentence when possible.
- Add the entry at the bottom of the most fitting category. New categories and improvements to the existing categorization are welcome.
- Check spelling and grammar, and remove trailing whitespace.
- Give the pull request a useful title, such as `Add ralph-foo`.

## Quality Standards

Resources must be:

- **Ralph-specific.** The resource must be about Ralph loops or explicitly built for them. General coding agents, CI services, and developer tools that "can be used in a loop" do not qualify.
- **Substantive.** Articles must add something beyond a summary of existing posts. Videos must teach or analyze, not just react.
- **Maintained.** Repositories must not be archived, deprecated, or explicitly unmaintained. Repositories need a README that explains usage.
- **Accessible.** Links must be public and free to read. Paywalled content is not accepted.

The following are rejected:

- Dead links, archived repositories, and abandoned one-day projects.
- SEO content farms, AI-generated listicles, and duplicates of content already listed.
- Self-promotion of off-topic products, including the same pull request sent to many awesome lists.
- Anything related to tokens, coins, or other crypto schemes.

Self-submissions of Ralph-specific projects are welcome. Say in the pull request that you are the author.

## Updating Your Pull Request

If asked to make changes to your pull request, edit your original pull request rather than opening a new one.

## Reporting Issues

If you find a broken link, an archived repository, or an outdated resource, open an issue or submit a pull request to fix it.

Thank you for your contributions!
